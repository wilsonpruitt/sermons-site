## What shipped

- `quartz/components/Head.tsx` — removed the hardcoded
  `<meta name="robots" content="noindex, nofollow">` (added at the 2026-08-26
  scaffold, commit `8ac50d6`, specifically to keep this site out of search/crawl
  while it served as a private phone-access replacement for Obsidian Publish) — this
  is the actual posture flip Wilson ratified 2026-09-18 in `~/open-corpus/PLAN.md`
  §4. Also added: `<link rel="canonical">` and a `CreativeWork` JSON-LD block scoped
  to sermon-tagged pages.
- `quartz.config.yaml` — `content-index` plugin's `enableSiteMap` flipped
  `false` -> `true` (Quartz's own sitemap generator, unused until now).
- `content/robots.txt`, `content/llms.txt` — new. Quartz's `Assets` emitter copies
  any non-Markdown file from `content/` to the SAME relative output path (confirmed
  by reading `quartz/plugins/emitters/assets.ts`), so these land at the site root,
  not under `/static/` like `quartz/static/*` would.
- `content/rights.md` — new content page, this site's `/rights` equivalent:
  CC BY-NC 4.0 (author's own name, not the Wroot Press imprint — decision 3 from the
  PLAN.md Sermons scope-change entry), a Machine Use section, and an honest note that
  the text is exactly what synced from the vault, never machine-edited.
- `content/export.md` — generated by `scripts/build-export.mjs`, NOT hand-written.
  **Deliberately NOT in `.gitignore`** despite being generated, unlike every other
  site's generated manifest file in this plan — Quartz's content globber (`globby`,
  `gitignore: true`) treats a `.gitignore`'d path under `content/` as invisible to
  the SITE BUILD ITSELF, not just to git. Gitignoring it silently dropped the page
  from the build with no warning (`Found 330 input files` instead of 331) until this
  was caught and reverted. It gets committed and regenerated like `content/index.md`
  and `content/indexes/*.md` already are on every `sync.py --write` run.
- `scripts/build-export.mjs` — bulk export, one gzipped JSONL line per sermon
  (Appendix E schema). Also regenerates `content/export.md`'s page body, so the two
  never drift.
- `scripts/build-siblings.mjs` — `.txt`/`.json` siblings per sermon, run after
  `npx quartz build`.
- `package.json` — new `build` script chains `build-export.mjs` -> `quartz build` ->
  `build-siblings.mjs` (there was no top-level `build` script before this session;
  the framework's own `prebuild` hook for `install-plugins` never actually fires on
  this project's real build path, since `vercel.json`'s `buildCommand` calls
  `npx quartz build` directly rather than `npm run build` — that behavior predates
  this session and was left unchanged, just wrapped).
- `vercel.json` — `buildCommand` updated to the same three-step chain.
- `CONTENT-LICENSE` — added a Machine Use paragraph and a "what needs asking"
  paragraph. **Not a new file**: a prior session (2026-09-10, Opus 5, commit
  `407f0b8`) had already added this file with the CC BY-NC 4.0 grant, discovered
  only when `git push` was rejected as non-fast-forward and `git pull --rebase`
  brought it in — this session's first draft duplicated it as `LICENSE-CONTENT.txt`
  before the rebase surfaced the existing file; that duplicate was deleted and its
  Machine Use content folded into `CONTENT-LICENSE` instead. `LICENSE.txt` remains
  Quartz's own MIT license for the framework code, untouched.

## Decisions this rollout intentionally left alone (per PLAN.md §4's Sermons entry)

- `sync.py`'s existing publish filter (type + date + prose-word-count) is the ONLY
  content gate — no separate manual privacy pass was run over the 324 sermons before
  this flip, per Wilson's ratified decision 2. Board emails, funerals, and pastoral
  notes were never in this repo to begin with (`sync.py` only ever reads sermon-typed
  notes out of the vault), so the flip does not newly expose anything outside that
  boundary.
- The weekly update flow (`sync.py --write && git add -A && git commit && git push`)
  is unchanged; a future sync will also regenerate and commit `content/export.md`
  and pick up any new `.txt`/`.json` siblings on the next `npm run build`.
